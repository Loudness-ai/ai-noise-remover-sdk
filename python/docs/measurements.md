# Measurements, policies and benchmarks

Analysis decodes all samples instead of trusting header duration. It hashes the decoded interleaved float64 PCM and streams sample peaks, RMS, DC, near-full-scale counts/runs, stereo correlation and channel imbalance. Silence uses thresholded 100 ms windows and a minimum interval; discontinuities are sample-jump candidates, not a verdict that a recording contains an audible click. Coarse band energy uses one-pole crossovers, not a calibrated spectral analyzer. Waveform/timeline/event detail is capped while overall counters continue over the full recording.

Integrated loudness and true peak come from the local EBU R128 filter. Silent, shorter-than-400 ms, below-gate or unknown-multichannel-layout material may lack a valid integrated measurement. Such fields are `None`; loudness range is omitted below ten seconds. Absence is preserved through policy validation and reports. Near-full-scale samples describe a configured threshold and do not prove a signal was clipped earlier in its history.

A policy has integer `schema_version: 1`, a name, a rules list, optional `codecs`/`containers`, and `unavailable: "warning"` or `"fail"`. A rule names a documented metric and finite `min`/`max` bounds, with optional `severity: "warning"` or `"fail"`. Invalid/unknown fields are rejected. `failed` indicates hard failures; `passed` requires every rule to pass, so an unavailable warning does not count as a pass. See [speech-policy.json](../examples/speech-policy.json).

Comparison retains both analyses, duration/rate/channel changes, loudness/peak/RMS/silence/band differences and decoded PCM equality. Alignment examines up to three four-second mono windows at 400 Hz. Silent or periodic material may produce unavailable or ambiguous alignment; it must not be interpreted as verified synchronization. Windowed alignment is not a full-song identity test or a perceptual-quality metric.

Benchmark manifests are executable developer input. `executable` and `args` run without a shell, but a trusted command can still access its account's files and network. Do not accept manifests from uploads or unauthenticated routes. Declare processor version/settings and fixture license/checksum. Distinct fixture filenames prevent ambiguous summaries. Warmups run and are discarded; measured runs report median/p95 command time plus analysis/policy/comparison if requested. Version and hardware details support reproducing that local run. They do not prove superiority over another model or predict server throughput.

Run [benchmark_manifest.py](../examples/benchmark_manifest.py) from the package root to produce a manifest for the included credited speech sample. Then execute `loudness-audio benchmark manifest.json`. Installation may access package registries; the built-in processing functions do not make network requests. A benchmark's external commands are outside that guarantee.
